# Currency Rates

Сервис собирает официальные курсы Банка России, сохраняет историю в H2 и возвращает данные через HTTP API. Поддерживаются пять валют: **USD, EUR, CNY, GBP и JPY**. Для каждой доступны название, стоимость одной единицы в рублях, изменение в рублях и процентах за календарный день.

Источник данных — [XML-сервис Банка России](https://www.cbr.ru/development/SXML/). Внешние запросы выполняются через `RestTemplate`. API-ключи, отдельный сервер базы данных и настройка учётных записей не требуются.

## Запуск

Нужна **JDK 17–25**. Maven Wrapper включён в репозиторий: устанавливать Maven отдельно не нужно. При первой сборке необходим интернет для загрузки Maven и зависимостей; для получения курсов нужен доступ к `www.cbr.ru`.

### IntelliJ IDEA / Giga IDE

1. Клонировать репозиторий или скачать ZIP и распаковать его.
2. Открыть папку с `pom.xml` и дождаться импорта Maven.
3. Выбрать установленную JDK 17 или новее в Project SDK.
4. Запустить `CurrencyRatesApplication` кнопкой Run.

После запуска открыть [http://localhost:8080](http://localhost:8080): браузер автоматически перейдёт на `/answer` и покажет результаты в JSON. Сбор сегодняшних курсов начинается автоматически после старта и повторяется каждые шесть часов. Первая загрузка занимает несколько секунд, поэтому сразу после запуска список может быть пустым.

### Терминал

Windows PowerShell, из папки проекта:

```powershell
.\mvnw.cmd spring-boot:run
```

Linux / macOS:

```bash
./mvnw spring-boot:run
```

Сборка и запуск JAR:

```powershell
.\mvnw.cmd clean verify
java -jar target/currency-rates-1.0.0.jar
```

Остановка — `Ctrl+C` или Stop в IDE. При повторном запуске сохранённая история остаётся доступной.

## Проверка работы

Ниже приведена полная последовательность запросов. Их можно выполнить в PowerShell или через любой HTTP-клиент.

**1. Посмотреть поддерживаемые валюты:**

```powershell
Invoke-RestMethod 'http://localhost:8080/api/currencies'
```

**2. Запустить сбор курсов на конкретную дату:**

`POST http://localhost:8080/api/collections`

Тело запроса, `Content-Type: application/json`:

```json
{
  "date": "2024-04-02",
  "sourceUrl": "https://www.cbr.ru/scripts/XML_daily.asp"
}
```

```powershell
$body = '{"date":"2024-04-02","sourceUrl":"https://www.cbr.ru/scripts/XML_daily.asp"}'
$job = Invoke-RestMethod -Method Post `
  -Uri 'http://localhost:8080/api/collections' `
  -ContentType 'application/json' -Body $body
$job
```

Ответ `202 Accepted` содержит `id` задачи, дату и состояние. Заголовок `Location` указывает адрес её проверки. Сбор выполняется в фоне; HTTP-запрос не ждёт ответа внешнего сайта.

Поля `date` и `sourceUrl` необязательны: `{}` или запрос без тела запускает сбор за сегодня по московскому времени. Поддерживается указанный XML-источник ЦБ РФ; дату нужно передавать отдельно, без параметров в ссылке. Допустимые даты — от `2000-01-02` до сегодняшнего дня включительно.

**3. Дождаться завершения задачи:**

`GET http://localhost:8080/api/collections/{id}`

```powershell
do {
  Start-Sleep -Milliseconds 500
  $status = Invoke-RestMethod "http://localhost:8080/api/collections/$($job.id)"
} while ($status.status -in @('QUEUED', 'RUNNING'))
$status
```

Успешный результат: `status = COMPLETED`, `savedRates = 5`, `error = null`. При недоступности источника задача получает `FAILED` и пояснение в `error`. В таком случае можно повторить POST. Приложение не подменяет сетевые ошибки демонстрационными курсами.

**4. Получить сохранённые результаты:**

```powershell
Invoke-RestMethod 'http://localhost:8080/answer?date=2024-04-02' | ConvertTo-Json -Depth 5
```

**5. Получить курс конкретной валюты на конкретную дату:**

```powershell
Invoke-RestMethod 'http://localhost:8080/api/rates/USD?date=2024-04-02'
```

**6. Проверить сортировку, фильтрацию и страницы:**

```powershell
Invoke-RestMethod 'http://localhost:8080/answer?date=2024-04-02&sortBy=RATE&direction=DESC&page=0&size=2' | ConvertTo-Json -Depth 5
Invoke-RestMethod 'http://localhost:8080/answer?date=2024-04-02&currency=JPY' | ConvertTo-Json -Depth 5
```

Повторный сбор на ту же дату обновляет пять записей, не создавая дубликатов. Можно загрузить несколько разных дат: задачи будут выполняться параллельно.

## API

| Метод и адрес | Назначение |
| --- | --- |
| `GET http://localhost:8080/api/currencies` | Поддерживаемые коды валют |
| `POST http://localhost:8080/api/collections` | Начать сбор; JSON с необязательными `date` и `sourceUrl` |
| `GET http://localhost:8080/api/collections/{id}` | Состояние задачи |
| `GET http://localhost:8080/answer` | Курсы на последнюю сохранённую запрошенную дату |
| `GET http://localhost:8080/api/rates` | Альтернативный адрес `/answer` с теми же параметрами |
| `GET http://localhost:8080/api/rates/USD?date=2024-04-02` | Одна валюта на указанную дату; `date` обязателен |

Параметры `/answer` и `/api/rates`:

| Параметр | Значения | По умолчанию |
| --- | --- | --- |
| `date` | Дата `YYYY-MM-DD` | Последняя сохранённая запрошенная дата |
| `currency` | `USD`, `EUR`, `CNY`, `GBP`, `JPY` | Все пять валют |
| `sortBy` | `CURRENCY`, `RATE`, `DATE`, `CHANGE`, `CHANGE_PERCENT` | `CURRENCY` |
| `direction` | `ASC`, `DESC` | `ASC` |
| `page` | Номер страницы, начиная с 0 | `0` |
| `size` | От 1 до 100 | `20` |

Ответ списка содержит `content`, `page`, `size`, `totalElements`, `totalPages`. При отсутствии записей возвращается пустой список. Эти GET-запросы читают H2 и сами не запускают загрузку из интернета.

Поля курса:

| Поле | Значение |
| --- | --- |
| `requestedDate` | Дата, на которую запрошены данные |
| `rateDate` | Дата действия курса из XML ЦБ РФ |
| `previousRateDate` | Дата действия курса, полученного для предыдущего календарного дня |
| `currency`, `name` | Код и название валюты |
| `baseCurrency` | Валюта расчёта, `RUB` |
| `nominal` | Исходный номинал в XML, например 100 для JPY |
| `rate`, `previousRate` | Рубли за **одну** единицу валюты на запрошенный и предыдущий день |
| `change` | `rate - previousRate`, рубли за одну единицу |
| `changePercent` | `(rate - previousRate) / previousRate × 100` |
| `collectedAt` | Время сохранения, UTC |
| `sourceUrl` | Источник данных |

Расчёты выполняются через `BigDecimal`: курс хранится с восемью знаками после запятой, процентное изменение — с шестью, округление `HALF_UP`. В выходные и праздники ЦБ может вернуть ранее установленный курс. Поэтому `requestedDate` и `rateDate` могут отличаться, а изменение за календарный день может быть нулевым. Сервис возвращает официальные курсы, а не биржевые котировки в реальном времени.

Ошибки параметров возвращают `400`, отсутствующий курс или задачу — `404`, переполнение очереди — `429`. Ошибки API имеют JSON-формат `ProblemDetail`. Сетевая ошибка уже принятой задачи отражается в её состоянии `FAILED`; ранее сохранённые данные остаются доступны.

## Хранение и выполнение задач

Приложение построено на Spring Boot и Spring MVC: контроллер принимает запросы, сервисы управляют сбором и чтением, JPA-репозиторий работает с H2. Представление API — JSON.

- Собственный `ThreadPoolExecutor` выполняет до четырёх сборов одновременно. `ArrayBlockingQueue` ограничивает очередь 32 ожидающими задачами; переполнение обрабатывается явно.
- `ScheduledExecutorService` ставит задачу после запуска и затем каждые шесть часов.
- `ConcurrentHashMap` хранит неизменяемые снимки состояний задач. Под монитором `synchronized` проверяется наличие уже выполняющейся задачи на ту же дату: повторный запрос получает тот же `id`.
- `ReentrantLock` защищает сохранение пакетов; все пять валют записываются одной транзакцией. Уникальное ограничение H2 на дату и код валюты дополнительно защищает от дубликатов.
- Результаты извлекаются из H2 и преобразуются в неизменяемые DTO в потоке транзакции. Фильтрация и сортировка выполняются через `parallelStream()`, затем формируется страница ответа.
- Отдельный демон-поток `Thread` с `Runnable` читает `BlockingQueue` и дописывает события в `logs/collections.log`. Запись файла не задерживает обработку HTTP-запросов. При заполнении очереди событие выводится в обычный лог приложения.
- При остановке планировщик отменяется, пул получает до 25 секунд на завершение задач, журнал дописывает очередь.

H2 хранится в `data/currency-rates.mv.db` относительно рабочей папки. История курсов сохраняется между запусками. Состояния задач хранятся только в памяти: удерживается до 200 последних задач, завершённые удаляются по мере добавления новых; после перезапуска их `id` недоступны.

Консоль H2: `http://localhost:8080/h2-console`. Параметры подключения:

```text
JDBC URL: jdbc:h2:file:./data/currency-rates;DB_CLOSE_ON_EXIT=FALSE
User Name: sa
Password: оставить пустым
```

Пример запроса:

```sql
SELECT * FROM exchange_rates ORDER BY requested_date DESC, currency_code;
```

HTTP-сервер по умолчанию доступен только на локальном компьютере. Порт, путь базы, период сбора и путь журнала заданы в `src/main/resources/application.yml`; для обычного запуска менять их не требуется.

## Тесты

```powershell
.\mvnw.cmd verify
```

Тесты проверяют разбор XML и кодировки Windows-1251, нормализацию номинала, расчёт изменений, загрузку через API, H2, повторное сохранение, выходные дни, фильтрацию и сортировку, обработку ошибок, параллельный запуск, переполнение очереди, общий `id` для повторных запросов и работу расписания.

В тестах ответы ЦБ подставляет `MockRestServiceServer`, база работает в памяти, автоматический сбор основного контекста отключён. Доступ к сайту ЦБ для тестов не требуется. Сборка и тесты также запускаются в GitHub Actions на JDK 17.
